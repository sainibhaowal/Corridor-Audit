## 1. SSE Status Indicator — Invalid Tailwind Class

**File:** `src/components/corridor-workspace.tsx` (lines 791, 1473)

### Symptom
The disconnected-state dot for the SSE stream and the footer "Runtime connected / Reconnecting" indicator rendered as an invisible element in production builds. The class `bg-[#2c2111]0` is not valid Tailwind syntax (the trailing `0` is not part of any color scale).

### Root Cause
Copy-paste error when authoring the disconnected color. The intention was a muted amber/orange dot for the disconnected state.

### Fix
```diff
- sseConnected ? "bg-emerald-600" : "bg-[#2c2111]0",
+ sseConnected ? "bg-emerald-600" : "bg-amber-600",
```

Applied at two locations:
1. Header status row (line 791): "SSE Stream Active / SSE Reconnecting..."
2. Footer status bar (line 1473): "Runtime connected / Reconnecting"

### Verification
- `npm run build` — no Tailwind purge warnings
- Visual inspection: disconnected state shows amber dot, connected shows emerald
- TypeScript typecheck: clean

## 2. Settings Sidebar — GitHub Icon Overlap

**File:** `src/components/settings-view.tsx` (line 363)

### Symptom
The absolute-positioned GitHub repository and issues links (`right-2 bottom-2`) overlapped the last settings tile ("Team & Webhook Security") because the parent `Card` only had `p-3` padding (12 px), insufficient for the 16×16 icons with 4 px gap.

### Root Cause
The sidebar `Card` did not reserve space for the fixed-position icon cluster.

### Fix
```diff
- <Card className="relative flex flex-col gap-1 p-3">
+ <Card className="relative flex flex-col gap-1 p-3 pb-10">
```

The `pb-10` (40 px) provides adequate clearance for the icon row.

### Verification

- No layout shift on settings tab navigation
- TypeScript typecheck: clean

## 3. Hot-Folder Watcher — Stale `seenFiles` Set Never Re-arms

**File:** `src/runtime/orchestrator.ts` (lines 50–125)

### Symptom
Dropping an updated file with the same filename into `data/inbox/` was silently ignored. The watcher's `seenFiles` `Set` only tracked filenames, so a second `change` event for the same name was deduplicated even though the file content changed.

### Root Cause
The original implementation used a `Set<string>` populated on first sight of a filename. No mechanism existed to detect file modification or to re-arm after a legitimate re-drop.

### Fix
Changed `seenFiles` to a `Map<string, string>` where the value is a signature `${mtimeMs}:${size}`:

```typescript
// Before
const seenFiles = new Set<string>()
// ...
if (!filename || seenFiles.has(filename)) return
// ...
seenFiles.add(filename)

// After
const seenFiles = new Map<string, string>()
// ...
if (!filename) return
const fullPath = resolve(hotFolder, filename)
let stats
try { stats = statSync(fullPath) } catch { return }
if (!stats.isFile()) return
const signature = `${stats.mtimeMs}:${stats.size}`
if (seenFiles.get(filename) === signature) return
seenFiles.set(filename, signature)

// Inside the debounced handler, re-verify before processing
const current = statSync(fullPath)
if (`${current.mtimeMs}:${current.size}` !== signature) return
```

Additional hardening:
- Skip directories and non-files via `stats.isFile()`
- Re-verify signature after the 250 ms debounce to avoid partial writes
- No longer calls `existsSync` before `statSync` (single syscall)

### Verification
- Manual test: drop `test.csv` → ingested; edit and re-drop → ingested again with new `ingestionId`
- `npm test` — 93/93 pass (includes ingestion and hot-folder tests)
- TypeScript typecheck: clean

## 4. Stale Production Bundle — `scripts/start.mjs` Served Old `.next`

**File:** `scripts/start.mjs`

### Symptom
After pulling latest code and running `npm start`, the server served a previously built `.next` bundle instead of rebuilding. The runtime status endpoint reported `sourceRevision` from an old commit and `workingTree: "modified"`.

### Root Cause
The start script only built when `.next/BUILD_ID` was missing:
```javascript
if (!existsSync(resolve(process.cwd(), ".next/BUILD_ID"))) {
  await runCommand(process.execPath, [nextCli, "build"])
}
```
It did not compare source mtimes against the build artifact.

### Fix
Added `bundleIsStale()` that computes the newest mtime across all tracked source inputs and compares it to the `BUILD_ID` mtime:

```javascript
const SOURCE_INPUTS = [
  "src", "public", "next.config.mjs", "package.json",
  "tailwind.config.ts", "postcss.config.mjs", "tsconfig.json"
]

function newestMtimeMs(target) { /* recursive directory walk */ }

function bundleIsStale() {
  const buildIdPath = resolve(process.cwd(), ".next/BUILD_ID")
  if (!existsSync(buildIdPath)) return true
  const builtAt = statSync(buildIdPath).mtimeMs
  return SOURCE_INPUTS.some(input => newestMtimeMs(resolve(process.cwd(), input)) > builtAt)
}
```

The build message now distinguishes first run vs. rebuild:
```javascript
console.log(firstRun
  ? "Building CorridorAudit Next.js production bundle (first run)..."
  : "Rebuilding CorridorAudit (sources changed since the last build)...")
```

### Verification
- Edit `src/components/corridor-workspace.tsx` → `npm start` → rebuild triggers → `sourceRevision` updates
- No rebuild when sources unchanged (verified by mtime comparison)
- `npm run build` passes; `npm test` 93/93 pass

## 5. Case Inspector Modal — Preview Format Race Condition

**File:** `src/components/case-inspector-modal.tsx`

### Symptom
Switching the preview format tabs (PDF → CSV → TXT → JSON) briefly showed stale content from the previous format while the new fetch was in flight. For example, selecting CSV after PDF would render the PDF iframe content inside the CSV table area until the CSV response arrived.

### Root Cause
The `useEffect` keyed by `[activeTab, caseId, previewFormat]` did not clear `previewText` or `previewError` when `previewFormat` changed. Stale state persisted until the new fetch resolved.

### Fix
Added a `useRef` run counter that acts as a request ID:

```typescript
const previewEffect = useRef(0)

useEffect(() => {
  if (activeTab !== "preview" || !caseId) return
  const thisRun = ++previewEffect.current
  setPreviewLoading(previewFormat !== "pdf")
  setPreviewError(null)
  if (previewFormat === "pdf") {
    setPreviewText("")
    return
  }
  let cancelled = false
  fetch(`/api/report/${encodeURIComponent(caseId)}?format=${previewFormat}&preview=1`)
    .then(async (res) => { /* ... */ })
    .then((txt) => { if (!cancelled && thisRun === previewEffect.current) setPreviewText(txt) })
    .catch((err) => { if (!cancelled && thisRun === previewEffect.current) setPreviewError(...) })
    .finally(() => { if (!cancelled && thisRun === previewEffect.current) setPreviewLoading(false) })
  return () => { cancelled = true }
}, [activeTab, caseId, previewFormat])
```

Behavior:
- On format change, `thisRun` increments; any in-flight fetch from the old format sees `thisRun !== previewEffect.current` and discards its result
- `previewText`/`previewError` cleared immediately on format switch
- PDF format uses an `<iframe>` and does not trigger a text fetch

### Verification
- Manual UI test: rapid tab switching shows no stale content
- `npm test` 93/93 pass
- TypeScript typecheck: clean (added missing `useRef` import)

## 6. CSV Export — Negative Amounts Neutralized as Text

**Files:** `src/core/reports/export-formats.ts`, `tests/report-exports.test.ts`

### Symptom
Negative financial amounts (e.g., `-35.00` for unexplained variance) were emitted as `'-35.00` (leading apostrophe) in CSV output. This neutralized the formula risk but broke spreadsheet `SUM()` because the cell became text.

### Root Cause
`csvEscape()` applied formula neutralization to any value starting with `= + - @`:
```typescript
const safe = /^[=+\-@\t\r]/.test(raw) ? `'${raw}` : raw
```
The `-` in `-35.00` matched, so a plain negative number was quoted.

### Fix
Only neutralize when the value is **not** a plain number:

```typescript
function csvEscape(value: string | number | undefined | null): string {
  const raw = value === undefined || value === null ? "" : String(value)
  const isPlainNumber = /^[+-]?\d+(?:\.\d+)?$/.test(raw)
  const safe = !isPlainNumber && /^[=+\-@\t\r]/.test(raw) ? `'${raw}` : raw
  if (/[",\r\n]/.test(safe)) {
    return `"${safe.replace(/"/g, '""')}"`
  }
  return safe
}
```

- `-35.00` → `-35.00` (numeric, summable)
- `=HYPERLINK("bad")` → `'=HYPERLINK("bad")` (neutralized)
- `+35.00` → `+35.00` (numeric)
- `@total` → `'@total` (neutralized)

### Regression Test
Added to `tests/report-exports.test.ts`:
```typescript
const negativeCsv = buildVerdictsCsv([{
  ...SAMPLE_VERDICT,
  caseId: "NEG-1",
  numbers: { ...SAMPLE_VERDICT.numbers, unexplainedVarianceMinor: -3500 },
}])
assert.match(negativeCsv, /,-35\.00,/)   // numeric
assert.doesNotMatch(negativeCsv, /,'-35\.00,/) // not text
```

### Verification
- `npm test` — 93/93 pass (new test passes)
- Manual CSV open in Excel/LibreOffice: negative cells are numeric, `SUM()` works
- TypeScript typecheck: clean
